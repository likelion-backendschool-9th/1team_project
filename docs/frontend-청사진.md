# 찍먹 프론트엔드 청사진

> 프론트엔드 개발의 전체 로드맵이다. 라우트·폴더·코딩 규칙은 [FRONTEND.md](./FRONTEND.md), 기능·API 명세는 [기획서](./기획서.md)를 참조한다.

---

## 1. 주요 사용자 흐름

### 비회원

1. 메인 `/`에서 인기 데모·피드·순위·기사를 탐색한다.
2. 데모 상세 `/demos/[id]`에서 정보를 확인한다. "찍먹하기"(실행)·좋아요·댓글·DM은 로그인 유도 팝업을 띄운다.
3. 블로그 `/blog/[id]`, 미니홈피 `/home/[userId]`, 검색 `/search`, 순위 `/rankings`는 자유롭게 조회한다.
4. 소셜 로그인(`/login`)으로 GitHub·카카오·구글 중 선택해 가입/로그인한다.

### 회원 — 데모

1. `/demos/upload`에서 zip 파일을 업로드한다. 확장자·용량 검사 결과를 즉시 보여준다.
2. 업로드 성공 → `/demos/[id]` 상세로 이동한다.
3. 다른 사람의 데모에서 "찍먹하기" 클릭 → 새 창에서 샌드박스 실행. `play_count` 증가.
4. 댓글(질문·버그·칭찬), 좋아요 토글, 북마크(나중에 해보기) 토글.

### 회원 — 미니홈피

1. `/home/[userId]`에서 프로필·대표 데모·프로젝트관·방명록·방문자 통계를 확인한다.
2. 본인 홈피: `/home/[userId]/edit`에서 스킨·대표 데모·소개 수정.
3. 다른 사람 홈피: 방명록 작성 (비밀글 옵션), 팔로우·구독 버튼.
4. "파도타기" → 랜덤 미니홈피로 이동.

### 회원 — 블로그

1. `/blog/write`에서 마크다운 글 작성. 데모 연결(선택), 유료/무료 설정.
2. 작성 성공 → `/blog/[id]`로 이동.
3. 유료 글은 구독자 또는 도토리 결제자만 전문 조회. 비구독자에게는 미리보기.
4. `/blog/[id]/edit`에서 본인 글 수정. 삭제는 상세에서 확인 후 처리.

### 회원 — 피드

1. `/feeds`에서 팔로잉/추천 탭으로 피드 조회.
2. 피드 작성: 짧은 글 + 투표(선택). 작성 후 목록 상단에 반영.
3. 좋아요 토글, 리포스트, 투표 참여. 작성자 프로필 → 미니홈피 이동.

### 회원 — DM

1. 상대 프로필·미니홈피에서 DM 버튼 → `/dm/[userId]`.
2. WebSocket으로 실시간 메시지 전송·수신. 읽음 표시.
3. 초기 대화 내역은 서버에서 조회, 이후 새 메시지는 WebSocket으로 수신.

### 회원 — 결제/구독

1. `/my/coins`에서 도토리 충전.
2. 상대 미니홈피에서 구독 버튼 → 구독 결제 (도토리 차감). 구독하면 유료 콘텐츠 열람 가능.
3. 개별 유료 콘텐츠는 도토리로 1건씩 결제.
4. `/my/subscriptions`에서 구독 목록 확인·해지.

### 관리자

1. `/admin` 대시보드에서 통계 확인 (가입자, 데모 업로드, 신고, 매출).
2. 공통 목록 패턴: 검색, 상태 필터, 정렬, 페이지 이동.
3. 회원 관리: 목록 → 상세 → 제재(일/주/월/영구) · 해제.
4. 콘텐츠 관리: 데모·블로그·피드·댓글 목록 → 삭제.
5. 신고 관리: 신고 목록 (대기 우선) → 처리 (숨김·제재·기각 + 사유).
6. 정산: 게시자별 수익, 수수료, 정산 확정.
7. 가상화폐: 충전 내역, 환불 처리, 부정 사용 확인.

## 2. 화면 설계 원칙

- **공통:** 헤더/사이드바, 로그인 상태, 반응형 레이아웃, 접근 가능한 폼·대화상자·상태 메시지를 먼저 만든다.
- **목록:** 결과 수, 검색/필터, 빈 결과, 로딩, 오류, 페이지 이동을 공통 패턴으로 만든다. 필터 상태는 URL 쿼리에 보존해 공유와 뒤로 가기를 지원한다.
- **상세:** 핵심 정보와 가능한 행동을 분리한다. 데모 상세에서는 실행·소셜 행동을 눈에 띄게 배치한다.
- **폼:** 필수값, 입력 형식, 서버 검증 오류, 저장 중 상태, 저장 성공 후 이동을 일관되게 처리한다. 중복 제출을 막는다.
- **변경 작업:** 삭제·차단·제재는 확인 대화상자를 띄우고 결과를 명확히 알린다.
- **모바일:** 회원 화면(피드·데모·미니홈피·DM)은 작은 화면을 우선 설계한다. 관리자 표는 좁은 화면에서 카드/가로 스크롤 등 읽기 가능한 대안을 제공한다.
- **실시간:** DM·알림은 WebSocket 연결 상태를 표시한다. 연결이 끊기면 재연결 시도 중임을 안내한다.

## 3. 확정이 필요한 항목

| 우선도 | 항목 | 이유 |
| --- | --- | --- |
| 높음 | 소셜 로그인 콜백 URL·JWT 쿠키 설정 | 인증 흐름 전체에 영향 |
| 높음 | 데모 zip 업로드 용량 제한·허용 확장자 | 업로드 폼 검증 규칙 |
| 높음 | 유료 콘텐츠 접근 제어 방식 | 구독자/결제자 판별 → 서버에서 검증 vs 프론트에서 분기 |
| 높음 | DM WebSocket 엔드포인트·메시지 포맷 | 실시간 채팅 구현에 직접 영향 |
| 높음 | 도토리 충전 PG 연동 방식 | 결제 화면과 민감 정보 처리 |
| 중간 | 검색 방식 (키워드 vs 벡터) | 검색 UI와 결과 표시 |
| 중간 | 알림 전달 방식 (폴링 vs WebSocket) | 실시간 알림 UI |
| 중간 | 미니홈피 스킨·테마 저장 구조 | 꾸미기 UI. 우선순위 낮으므로 MVP 이후 |
| 중간 | 깃허브 연동 범위 (잔디·레포·언어 통계) | API 호출 시점과 캐싱 전략 |
| 낮음 | 카카오톡 공유 SDK 설정 | Phase 4 부가 기능 |
| 낮음 | 명함·QR코드 생성 방식 | Phase 4 부가 기능 |

## 4. 개발 단계 체크리스트

기획서의 Phase 1~4에 맞춘다. 각 단계에서 화면·상태·데이터 흐름까지 연결하고 검증한다.

### 선행 준비

- [ ] Next.js App Router + TypeScript `strict` + `src/app/` 구조 확인
- [ ] 라우트 그룹 생성: `(public)/`, `(user)/`, `admin/`
- [ ] 그룹별 layout.tsx (헤더·사이드바·`<main>`)
- [ ] 공통 UI: 로딩(`loading.tsx`), 오류(`error.tsx`), 빈 상태, 404
- [ ] 공통 요청기 `_lib/api/client.ts` (server-only, 쿠키 전달)
- [ ] `next.config.ts` rewrites로 `/api/v1/*` 프록시
- [ ] `.env.local.example` 커밋 (API_ORIGIN, NEXT_PUBLIC_SITE_URL)
- [ ] 루트 metadata (title template, OG, metadataBase)

### Phase 1 — 핵심 (MVP)

#### 1-1. 인증

- [ ] `/login` 소셜 로그인 화면 (GitHub·카카오·구글 버튼)
- [ ] OAuth 콜백 처리 → JWT 쿠키 저장
- [ ] 로그인 상태에 따른 헤더 분기 (로그인/프로필)
- [ ] 미들웨어 또는 layout에서 인증 필요 페이지 보호

#### 1-2. 미니홈피

- [ ] `/home/[userId]/edit` 미니홈피 수정 (스킨, 대표 데모, 소개) — 본인만
- [ ] 방문 카운트 증가 (`POST mini-home/{userId}/visit`)
- [ ] 미니홈피 → 데모 목록·블로그 목록으로 이동하는 동선

#### 1-3. 데모

- [ ] `/demos` 데모 탐색 (태그 필터, 인기/최신 정렬, 페이지네이션)

- [ ] `/demos/upload` 데모 업로드 (zip, 확장자·용량 검사, 진행 상태)
- [ ] "찍먹하기" → 새 창에서 데모 실행, play_count 증가
- [ ] 업로드 성공 → 상세로 이동, 삭제 → 목록으로 이동

#### 1-4. 블로그

- [ ] `/blog/[id]/edit` 글 수정, 삭제

#### 1-5. 팔로우
