# 찍먹 배포 가이드

> 서버 환경 세팅부터 자동배포까지의 전체 과정

---

## 1. 전체 구조

```
GitHub (dev 머지)
  → GitHub Actions (이미지 빌드)
  → GHCR (이미지 저장소)
  → 서버 SSH 접속 → docker compose pull → up
```

```
서버 (cloud.newlecture.com)
├── dipsource-proxy  (Nginx :3001)  → 외부 접속 포트
├── dipsource-frontend (Next.js :3000)
├── dipsource-backend  (Spring Boot :8080)
└── dipsource-db       (PostgreSQL 16 :5432)
```

---

## 2. 서버 정보

| 항목 | 값 |
|------|-----|
| 호스트 | `cloud.newlecture.com` |
| SSH 유저 | `dipsource` |
| SSH 비밀번호 | GitHub Secrets `SSH_PASSWORD` 참고 |
| 접속 포트 | `3001` (Nginx) |
| 접속 URL | `http://cloud.newlecture.com:3001` |

## 3. 서버 초기 세팅 (최초 1회)

### 3-1. SSH 접속

```bash
# 호스트 키 에러 나면 먼저 실행
ssh-keygen -R cloud.newlecture.com

# 접속
ssh dipsource@cloud.newlecture.com
```

### 3-2. 서버에서 폴더 생성

```bash
mkdir -p ~/app/nginx
```

### 3-3. 로컬에서 파일 전송 (Mac 터미널에서 실행)

서버에서 `exit`으로 나온 후 실행:

```bash
# docker-compose.yml (서버용 = prod)
scp docker-compose.prod.yml dipsource@cloud.newlecture.com:~/app/docker-compose.yml

# Nginx 설정
scp nginx/default.conf dipsource@cloud.newlecture.com:~/app/nginx/default.conf

# 환경변수
scp .env dipsource@cloud.newlecture.com:~/app/.env
```

### 3-4. 서버에서 확인

```bash
ssh dipsource@cloud.newlecture.com "ls -la ~/app/"
```

아래 파일이 있으면 정상:
```
~/app/
├── .env
├── docker-compose.yml
└── nginx/
    └── default.conf
```

## 4. GitHub Secrets 설정

GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret

| Secret 이름 | 값 | 용도 |
|-------------|-----|------|
| `SSH_PASSWORD` | 서버 SSH 비밀번호 | 배포 시 서버 접속 |
| `GHCR_TOKEN` | GitHub Personal Access Token | 서버에서 이미지 pull |

### GHCR_TOKEN 발급 방법

1. GitHub → 프로필 → Settings → Developer settings
2. Personal access tokens → Tokens (classic)
3. Generate new token (classic)
4. 권한: `read:packages`, `write:packages` 체크
5. 생성된 토큰을 `GHCR_TOKEN` 값으로 등록

## 5. 자동배포 흐름

### 트리거

`dev` 브랜치에 push (PR 머지 포함) 시 자동 실행

### 과정

```
1. GitHub Actions 시작
2. backend 이미지 빌드 → ghcr.io에 push
3. frontend 이미지 빌드 → ghcr.io에 push
   (2, 3은 병렬 실행)
4. 서버에 SSH 접속
5. docker compose pull (새 이미지 다운로드)
6. docker compose up -d (컨테이너 교체)
7. 사용하지 않는 이미지 정리
```

### 배포 확인

- GitHub → Actions 탭에서 워크플로우 상태 확인
- 성공 후 `http://cloud.newlecture.com:3001` 접속

## 6. 수동 배포 (긴급 시)

자동배포가 실패하거나 수동으로 해야 할 때:

```bash
# 서버 접속
ssh dipsource@cloud.newlecture.com
cd ~/app

# GHCR 로그인
echo "GHCR_TOKEN값" | docker login ghcr.io -u GitHub유저명 --password-stdin

# 이미지 태그 지정 (GitHub Actions 로그에서 확인)
export IMAGE_BACKEND=ghcr.io/likelion-backendschool-9th/1team_project-backend:커밋해시
export IMAGE_FRONTEND=ghcr.io/likelion-backendschool-9th/1team_project-frontend:커밋해시

# 배포
docker compose pull
docker compose up -d --remove-orphans
```

## 7. 서버 관리 명령어

```bash
# 서버 접속
ssh dipsource@cloud.newlecture.com
cd ~/app

# 컨테이너 상태 확인
docker compose ps

# 로그 확인
docker compose logs backend    # 백엔드 로그
docker compose logs frontend   # 프론트엔드 로그
docker compose logs db         # DB 로그
docker compose logs proxy      # Nginx 로그

# 특정 서비스 재시작
docker compose restart backend

# 전체 중지
docker compose down

# 전체 시작
docker compose up -d

# DB 접속
docker compose exec db psql -U dipsource -d dipsource
```

## 8. 로컬 개발 환경

로컬에서 도커로 전체 환경을 띄울 수도 있음:

```bash
# .env 파일 생성
cp .env.example .env
# POSTGRES_PASSWORD 채우기

# 실행 (override.yml이 자동 적용돼서 핫 리로드 됨)
docker-compose up -d

# 접속
# 프론트: http://localhost:3000
# Nginx:  http://localhost:80
```

`docker-compose.override.yml`이 자동 적용돼서 소스 코드 수정 시 자동 반영됨.

## 9. 파일 구조

```
프로젝트 루트/
├── docker-compose.yml          # 로컬 개발용 (빌드 포함)
├── docker-compose.override.yml # 로컬 핫 리로드 설정
├── docker-compose.prod.yml     # 서버용 (이미지 pull)
├── .env                        # 환경변수 (git 제외)
├── .env.example                # 환경변수 템플릿 (git 포함)
├── nginx/
│   └── default.conf            # Nginx 라우팅 설정
├── backend/
│   └── Dockerfile              # Spring Boot 빌드/실행
├── frontend/
│   └── Dockerfile              # Next.js 빌드/실행
└── .github/workflows/
    └── deploy.yml              # 자동배포 워크플로우
```
