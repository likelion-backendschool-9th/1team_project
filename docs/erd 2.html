정규화 체크

항목 상태 설명
users.coin_balance의도적 비정규화coin_transactions에서 계산 가능하나 매 조회마다 SUM 비용 큼. 트랜잭션 시 동기화
demos.like_count의도적 비정규화likes 테이블에서 COUNT 가능하나 목록 조회 성능 위해 캐싱. 좋아요 토글 시 ±1 업데이트
posts.like_count의도적 비정규화위와 동일
feeds.like_count / repost_count의도적 비정규화위와 동일
mini_homes.today_count / total_count의도적 비정규화방문 로그 테이블 없이 카운터로 관리. today_count는 매일 자정 리셋
users.tech_stacks (JSONB)적절단순 문자열 배열 ["Spring","React"]. 별도 테이블 불필요
feeds.poll_options (JSONB)적절투표 선택지 ["보안","성능","설계"]. 옵션 자체는 독립 엔티티 아님
comments (다형성 FK)트레이드오프target_type + target_id로 demo/post/feed 댓글 통합. DB 레벨 FK 제약 불가 → 앱 레벨 검증 필요
likes (다형성 FK)트레이드오프위와 동일. 테이블 분리(demo_likes, post_likes...) 시 FK 보장 가능하나 관리 복잡도 증가
subscriptions.monthly_price적절구독 시점 가격 스냅샷. mini_homes.subscription_price가 변경되어도 기존 구독 가격 유지

UNIQUE / CHECK 제약조건

테이블 제약조건 목적
usersUQ(email), UQ(nickname)이메일/닉네임 중복 방지
social_accountsUQ(provider, provider_id)같은 소셜 계정 중복 연동 방지
mini_homesUQ(user_id)1인 1홈피
tagsUQ(name)태그명 중복 방지
demo_tagsUQ(demo_id, tag_id)같은 태그 중복 부착 방지
followsUQ(follower_id, following_id)
CHECK(follower_id ≠ following_id)		중복 팔로우 방지, 자기 자신 팔로우 불가
likesUQ(user_id, target_type, target_id)중복 좋아요 방지
bookmarksUQ(user_id, demo_id)중복 북마크 방지
feed_votesUQ(feed_id, user_id)1인 1표
repostsUQ(user_id, feed_id)중복 리포스트 방지
