# 데모 플랫폼 배포·설정 가이드

> 사용자가 올린 데모를 Cloudflare R2 + Workers로 실행하기 위해 **사람이 직접 설정해야 하는 것**을 모은 문서다.
> 강사님 도메인의 DNS는 건드리지 않는다. 데모는 `*.workers.dev` 주소에서 실행된다.

## 1. 구성

| 역할 | 위치 |
| --- | --- |
| 정적 파일 저장 | R2 버킷 `dipsource-demos` (비공개) |
| 파일 제공·접근 제어 | Worker `dipsource-demo-runner` (`workers/demo-runner`) |
| 메타데이터·검증·공개 관리 | Spring Boot |
| 실행 | 사용자 브라우저의 sandbox iframe |

## 2. R2 버킷

1. Cloudflare 대시보드 → R2 → 버킷 `dipsource-demos` 생성.
2. **Public Access는 켜지 않는다.** r2.dev 주소와 커스텀 도메인 모두 연결하지 않는다.
3. R2 → Manage API Tokens → `dipsource-demos`에 Object Read & Write 권한 토큰 발급. Access Key·Secret을 서버 `.env`에 넣는다.

## 3. Worker 배포

```bash
cd workers/demo-runner
npm ci
npx wrangler login
# wrangler.toml의 ALLOWED_FRAME_ANCESTORS를 실제 사이트 주소로 바꾼다 (공백으로 여러 개)
npx wrangler deploy
```

출력되는 `https://dipsource-demo-runner.<계정>.workers.dev`가 `DEMO_WORKER_BASE_URL`이다.

임시 미리보기와 썸네일 촬영에 쓰는 서명 키를 Worker와 서버에 **같은 값**으로 넣는다.

```bash
openssl rand -base64 32          # 값 생성
npx wrangler secret put DEMO_SIGNING_SECRET
```

## 4. 서버 `.env`

```
R2_ENABLED=true
R2_ENDPOINT=https://<계정ID>.r2.cloudflarestorage.com
R2_ACCESS_KEY=...
R2_SECRET_KEY=...
R2_BUCKET=<이미지용 공개 버킷>
R2_PUBLIC_URL=<이미지용 공개 주소>
R2_DEMO_BUCKET=dipsource-demos
DEMO_WORKER_BASE_URL=https://dipsource-demo-runner.<계정>.workers.dev
DEMO_SIGNING_SECRET=<Worker에 넣은 값과 동일>
```

`R2_ENABLED=true`는 기존 이미지 업로드도 함께 켠다. 기존처럼 비워 두면 데모 목록·상세는 동작하고 파일 업로드만 503을 준다.

## 5. 프록시 업로드 크기

ZIP은 최대 10MB다(요청 전체 12MB). 저장소의 `nginx/default.conf`에는 `client_max_body_size 12m`을 넣어 두었다.
**그 바깥의 프록시(강사님 서버 Nginx 등)에 더 작은 제한이 있으면 큰 ZIP이 413으로 끊긴다.** 이 경우 서버 관리자에게 API 경로의 제한을 12MB 이상으로 요청해야 한다. 이 저장소에서는 바깥 프록시 설정을 바꾸지 않는다.

## 6. iframe 허용

찍먹 사이트는 CSP `frame-src`를 쓰지 않아 별도 변경이 필요 없다. 나중에 사이트에 CSP를 도입하면 `frame-src https://dipsource-demo-runner.<계정>.workers.dev`를 추가한다.
Worker 쪽은 `ALLOWED_FRAME_ANCESTORS`로 찍먹 사이트에서만 iframe에 띄울 수 있게 제한한다.

## 7. 자동 썸네일 (선택)

Cloudflare Browser Run(구 Browser Rendering)의 screenshot API를 쓴다. 신뢰할 수 없는 데모를 강사님 서버의 브라우저에서 실행하지 않기 위해서다.

1. 대시보드 → My Profile → API Tokens → Custom Token. 권한은 Account의 **Browser Run - Edit**(화면에 따라 Browser Rendering - Edit로 표시).
2. 서버 `.env`에 `DEMO_THUMBNAIL_ENABLED=true`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_BROWSER_API_TOKEN`을 넣는다.

2026-11 기준 공식 문서의 제한:

| 플랜 | 브라우저 시간 | 호출 |
| --- | --- | --- |
| Workers Free | 하루 10분 (UTC 0시 초기화, 초과 시 429) | 10초에 1회 |
| Workers Paid | 월 10시간 포함, 이후 시간당 $0.09 | 초당 30회 (문서 기본값) |

서버는 15초에 하나씩만 찍어 무료 플랜 호출 제한을 넘지 않는다. 실패하면 3회까지(2분, 4분 뒤) 재시도하고 기본 썸네일로 둔다.

## 8. 임시 미리보기 파일 안전망 (선택)

임시 미리보기는 서버의 정리 작업이 만료 후 지운다. 서버가 오래 멈출 때를 대비해 R2 → 버킷 → Settings → Object lifecycle rules에서 `previews/` 접두사를 1일 후 삭제하도록 추가할 수 있다.

## 9. DB

마이그레이션 도구 없이 `ddl-auto=update`와 `schema.sql`을 쓴다. `demo_versions` 테이블과 새 컬럼은 앱 기동 시 생기고, 옛 `demos_status_check` 제약은 `schema.sql`이 지운다. 별도 작업은 없다.
