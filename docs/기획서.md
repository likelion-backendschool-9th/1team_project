# 찍먹 (Dip Source) — 프로젝트 기획서

> 개발자의 소스를 맛보다

---

## 1. 프로젝트 개요

### 1-1. 서비스 소개

| 항목 | 내용 |
|------|------|
| 서비스명 | 찍먹 (Dip Source) |
| 한 줄 소개 | 개발자들이 프로젝트를 데모로 공유하고, 미니홈피를 꾸미고, 서로의 코드를 체험할 수 있는 개발자 SNS |
| 대상 사용자 | 주니어~시니어 개발자, 개발 공부 중인 학생, 코드 리뷰어/멘토 |

### 1-2. 기획 배경

현재 개발자들의 활동은 여러 플랫폼에 분산되어 있다.

| 플랫폼 | 역할 | 한계 |
|--------|------|------|
| GitHub | 코드 저장·협업 | 결과물을 바로 체험할 수 없음 |
| 개인 블로그 | 기술 글 작성 | 코드와 데모가 분리됨 |
| SNS (X, 스레드 등) | 짧은 글·소통 | 개발 특화 기능 없음 |
| 포트폴리오 사이트 | 프로젝트 전시 | 소셜 기능 부재 |

**찍먹**은 이 모든 기능을 하나로 합친다.
- GitHub처럼 코드를 올리되, **브라우저에서 바로 실행**할 수 있고
- 블로그처럼 글을 쓰되, **데모와 연결**되고
- SNS처럼 소통하되, **개발자에게 특화**된 기능을 제공하고
- 싸이월드처럼 **미니홈피**를 꾸며 자기만의 공간을 만든다

### 1-3. 핵심 가치

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   🍽 찍먹하기 = 남의 코드를 부담 없이 맛보는 것          │
│                                                         │
│   ① 올려라  →  프로젝트를 zip으로 업로드                 │
│   ② 찍먹해라 →  클릭 한 번으로 브라우저에서 실행          │
│   ③ 소통해라 →  댓글·좋아요·DM·피드로 교류               │
│   ④ 성장해라 →  블로그·구독·수익화로 개발자 브랜딩        │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 2. 기능 정리

### 2-1. 메인페이지

| 분류 | 기능 | 설명 |
|------|------|------|
| 회원 | 소셜 로그인 | 깃허브·카카오·구글, 한 계정에 여러 소셜 연동 |
| | 알림 | 실시간 알림 (팔로우, 좋아요, 댓글, DM 등) |
| | 차단/신고 | 신고 접수, 관리자가 숨김 처리 |
| | 관리자/사용자 대시보드 | 통계, 구독·결제 관리 |
| 피드/커뮤니티 | 스레드형 피드 | 짧은 글, 투표, 좋아요, 리포스트, 추천 피드. 작성자 홈피로 가는 경로 제공 (홍보 효과) |
| 검색/추천/순위 | 순위 | 팔로워, 게시물, 데모, 코드, 블로그, 홈피별 |
| | 검색 | 문장으로 검색 ("JWT 체험 가능한 프로젝트 찾아줘") + 포털 API, 벡터 API 사용 |
| | 추천 | 좋아요 기반 데모 추천, 글 추천 |
| 기타 | 명함 | 이름·스택·대표 프로젝트·홈피 주소 카드 + QR코드 |

### 2-2. 미니홈피

| 분류 | 기능 | 설명 |
|------|------|------|
| 미니홈피 | 프로필 | 소개, 기술스택 태그, 깃허브 잔디·대표 레포, 평점·뱃지, 언어 사용 통계 |
| | ★ 깃허브 불러오기 | 깃허브에서 README·레포 정보를 가져와 프로젝트에 자동 반영 |
| | 프로젝트관 | 공개 슬롯 수 제한 (대표작만 고르게), 메인 데모는 첫 화면에서 바로 실행 |
| | 방명록 | 비밀글, 데모 체험 후기 포함. 비밀글은 미니홈페이지 주인만 볼 수 있음 |
| | 방문자 통계 | TODAY/TOTAL, 같은 사람은 하루 1회만 집계 |
| | 꾸미기 | 뱃지, 스킨·테마·템플릿 (우선순위 낮음) |
| | 일촌평 | 이웃이 남기는 한 줄 평 |
| | 랜덤 방문 (파도타기) | 다른 홈피로 랜덤 이동 |
| 데모 | 업로드·실행 | zip 업로드, 용량·파일 검사, 리다이렉트(새로운 창) |
| | 보안 검사 | 악성 코드 확인. VirusTotal API 검토 중. 파일 확장자 html, css, js, png 등만 허용 |
| | 체험 소통/북마크 | 댓글(질문·버그·칭찬), 좋아요, 버전, 나중에 해보기, 체험 횟수 통계 |

### 2-3. 블로그

| 분류 | 기능 | 설명 |
|------|------|------|
| 블로그 | 기본 | 글, 댓글, 좋아요, 디자인 템플릿, 개발 일지 |
| | 수익화 | 유료 구독, 무료 미리보기 |
| | 연결 | 데모와 블로그 글 연결 |
| | ★ 외부 글·기사 검색 | 네이버·다음 블로그 검색 결과 + 관련 네이버 기사를 링크로 제공 (포털 API). 스레드 형식으로 개발자들이 의견을 나누는 공간. IT, AI, 개발 관련 기사 전부 |

### 2-4. 소셜

| 분류 | 기능 | 설명 |
|------|------|------|
| 소셜 | 팔로우 | 인스타그램 방식 팔로우/언팔로우 |
| | DM | 1:1 메시지 |
| | ★ 카톡 공유 | "찍먹해보세요" 하고 데모·홈피를 카카오톡으로 공유 |

### 2-5. 결제

| 분류 | 기능 | 설명 |
|------|------|------|
| 결제 | 구독 | 게시자가 자기 미니홈피 구독료를 직접 설정 (월 5,000원~10,000원 등) → 구독하면 그 사람의 모든 유료 콘텐츠 열람 가능. 비구독자는 썸네일·영상만. 도토리로 원하는 콘텐츠 1건씩 개별 결제 |
| | 가상 화폐 | 쿠키·도토리·코인·잔디 중 하나로 통일. 뱃지 구매, 선물, 유료 데모 체험 |
| | 신규 가입 크레딧 | 유료 n회 체험 → n일 동안 모든 콘텐츠 오픈 |
| | 홈피 플러스 | 추가 기능·확장 잠금 해제 |

### 2-6. 관리자

| 분류 | 기능 | 설명 |
|------|------|------|
| 대시보드 | 통계 요약 | 오늘 가입자, 데모 업로드 수, 신고 건수, 구독 매출 |
| 회원 관리 | 회원 목록/검색 | 닉네임, 이메일, 가입일 검색, 상태(활성/탈퇴/정지) 필터 |
| | 회원 상세 | 프로필, 활동 내역, 구독 현황, 코인 잔액, 신고 이력 |
| | 회원 제재 | 활동 정지 (일, 주, 월, 영구) |
| 콘텐츠 관리 | 데모 목록 | 전체 데모 검색/필터, 삭제 |
| | 블로그 목록 | 전체 게시글 검색/필터, 삭제 |
| | 피드 목록 | 피드 검색, 삭제 |
| | 댓글 관리 | 신고된 댓글 우선 표시, 삭제 |
| 신고 관리 | 신고 접수 목록 | 신고 유형별(데모/글/댓글/사용자) 필터, 상태(대기/처리완료) |
| | 신고 처리 | 콘텐츠 숨김, 작성자 제재, 신고 기각, 처리 사유 기록 |
| 구독/결제 | 구독 현황 | 전체 구독 건수, 활성/해지 비율 |
| | 매출 통계 | 구독 매출, 도토리 충전 매출, 기간별 그래프 |
| | 정산 관리 | 게시자별 수익 내역, 수수료 계산, 정산 상태 |
| 가상화폐 관리 | 충전 내역 조회 | 전체 코인 충전/사용 이력 검색, 사용자별 필터 |
| | 환불 처리 | 코인 환불 요청 승인/거절, 사유 기록 |
| | 부정 사용 확인 | 비정상 충전·사용 패턴 감지, 의심 계정 표시 |

## 7. 추후 적용 예정

### 커스텀 CSS 미니홈피

미니홈피의 기본 HTML 구조(프로필, 프로젝트관, 방명록 등)와 기본 CSS만 제공하고, 사용자가 CSS 에디터에서 직접 스타일을 수정할 수 있게 한다. 애니메이션, 색상, 레이아웃, 호버 효과 등을 자유롭게 커스텀할 수 있다.

- 미니홈피 수정 페이지에 CSS 에디터 내장
- 사용자가 작성한 CSS를 DB에 저장, 방문 시 `<style>` 태그로 주입
- CSS 적용 범위를 미니홈피 영역으로 제한 (보안)
- 잘 꾸민 CSS를 커뮤니티에서 공유하거나 도토리로 판매 가능

개발자 대상 서비스이기 때문에 코드로 직접 꾸미는 것 자체가 차별점이 되고, CSS 스킨이 데모와 함께 하나의 콘텐츠가 되는 구조다.

## 8. 제외 항목

| 기술 | 제외 사유 |
|------|----------|
| H2 Database | 인메모리 DB로 실습용. 운영에서는 PostgreSQL 사용 |
| QueryDSL | 동적 쿼리에 유용하지만 초기 세팅 복잡. Spring Data JPA 기본 쿼리 메서드 + JPQL로 충분 |
| Criteria API | QueryDSL보다 가독성 떨어짐. 사용할 이유 없음 |
| Vercel | Next.js 단독 배포용. Docker Compose로 통합 관리하므로 불필요 |
| Supabase / Firebase | BaaS 서비스. Spring Boot로 백엔드 직접 구현하므로 불필요 |
| mkcert | 로컬 SSL 인증서 도구. 배포 시 Nginx + Let's Encrypt 사용 |
| SAML | 기업용 SSO 프로토콜. 소셜 로그인은 OAuth2로 처리 |
