# 임시 목업·더미 데이터 현황

> 백엔드 API가 다 만들어지기 전에 DM을 화면에서 확인하려고 넣은 **임시 장치** 목록이다.
> AI 에이전트는 아래 "임시 코드" 항목을 건드리기 전에 이 문서를 먼저 읽는다. 이 문서는 해당 기능의 백엔드 API가 생기면 함께 갱신하거나 지운다.

---

## 1. 요약

| 구분 | 무엇 | 어디 |
| --- | --- | --- |
| 스위치 | `MOCK_EXCEPT_DM=1`이면 DM·로그인 정보만 실서버, 나머지는 목 데이터 | `frontend/src/app/_lib/api/client.ts` |
| 더미 데이터 | 팀 공용 시드(회원 70명·피드·팔로우). DM 대화는 없음 | `backend/scripts/dev-seed/seed-data.sql` |
| 로그인 | GitHub 로그인 없이 시드 계정으로 들어가는 개발용 로그인 (`TEMP-DEV-LOGIN`) | 프론트 `/login/dev`, 백엔드 `POST /api/v1/auth/dev-login` |

코드에서 `TEMP-DM-PREVIEW`로 검색하면 임시 코드가 모두 나온다.

## 2. 프론트 데이터 출처 규칙

`frontend/src/app/_lib/api/client.ts`

```ts
export const hasBackend = Boolean(API_ORIGIN);          // 백엔드 연결 여부
export const isMockMode = !hasBackend || process.env.MOCK_EXCEPT_DM === "1";
```

| 상황 | `hasBackend` | `isMockMode` | 결과 |
| --- | --- | --- | --- |
| `API_ORIGIN` 없음 (지금 배포 서버) | false | true | 전부 목 데이터 |
| `API_ORIGIN` 있음 + `MOCK_EXCEPT_DM=1` (DM 확인용) | true | true | DM·로그인 정보만 실서버, 나머지 목 데이터 |
| `API_ORIGIN` 있음 (백엔드 완성 후) | true | false | 전부 실서버 |

`isMockMode` 대신 `hasBackend`를 보는 곳(= 항상 실서버를 쓰는 곳):

| 파일 | 함수 | 이유 |
| --- | --- | --- |
| `(user)/_lib/dmApi.ts` | `getRooms`, `getMessages` | DM 백엔드는 구현돼 있음 |
| `(user)/_lib/api.ts` | `getMe` | DM에서 "내 메시지"를 구분하려면 실제 회원 ID가 필요. `MOCK_EXCEPT_DM`일 때는 응답에 없는 필드(뱃지·칩)를 `mockMe`로 채운다 |
| `(user)/_lib/session.ts` | `isLoggedIn`, `endSession` | 실서버 로그인 쿠키(`access_token`)로 판단 |
| `(public)/login/_actions.ts` | `startLogin` | 백엔드가 있으면 실제 OAuth로 보냄 |
| `(user)/_lib/api.ts` | `getFollowings` | 오른쪽 팔로잉 목록. 팔로우 백엔드는 구현돼 있음 |
| `(feed)/my/_lib/api.ts` | `getFollowings`, `getFollowers` | `/my/follows` 목록 |
| `(feed)/_actions.ts` | `toggleFollow` | 피드 팔로우 버튼 |
| `mini-home/[userId]/_actions.ts` | `toggleIlchon` | 미니홈피 일촌 맺기(= 팔로우) 버튼 |
| `blog/_lib/api.ts` | `getPosts`, `getPost`, `getUserPosts`, `getBlogOwner` | 블로그 글 목록·상세·주인(회원 정보만, 구독 정보는 비움) |
| `blog/_actions.ts` | `createPost`, `updatePost`, `deletePost` | 블로그 글 쓰기·수정·삭제 |

## 3. 백엔드 API 상태

**구현됨 (실서버로 확인 가능)**

| API | 비고 |
| --- | --- |
| `GET /api/v1/dm/rooms` | 대화방 목록, 안 읽은 수, 접속 중 |
| `GET /api/v1/dm/{userId}` | 대화 내역 (열면 읽음 처리) |
| WebSocket `/ws` → `/app/dm.send` | 실시간 전송, 받는 곳 `/user/queue/dm`, 오류 `/user/queue/errors` |
| `GET /api/v1/users/me` | 내 정보. 팔로워·팔로잉 수는 실제 값 (뱃지·칩은 아직 없음) |
| `GET /api/v1/users/nicknames/available`, `POST /api/v1/users/me/profile` | 온보딩 |
| `GET /api/v1/users/{userId}/github/*` | 미니홈피 GitHub 잔디·레포·언어 |
| `GET /api/v1/feeds` | 추천 피드 |
| `GET /api/v1/auth/login/{provider}`, `POST /api/v1/auth/logout` | 로그인 |
| `POST·DELETE /api/v1/follows/{userId}` | 팔로우·언팔로우 (멱등) |
| `GET /api/v1/follows/followings`, `GET /api/v1/follows/followers` | 팔로잉·팔로워 목록 (맞팔 여부 포함, `?q=` 닉네임 검색) |
| `GET /api/v1/follows/followings/presence?userIds=` | 화면에 나온 팔로잉의 접속 상태 |
| `GET·POST /api/v1/posts`, `GET·PUT·DELETE /api/v1/posts/{postId}`, `GET /api/v1/users/{userId}/posts` | 블로그 글 CRUD (분류 7개, 유료 글 잠금) |

**아직 없음 → 프론트가 목 데이터로 대신 보여 줌** (각 라우트의 `_lib/mock.ts`)

| 영역 | 프론트가 부르는 API | 목 데이터 위치 |
| --- | --- | --- |
| 오른쪽 프로필 카드 | `users/me`의 뱃지·칩 필드 | `(user)/_lib/mock.ts` `mockMe` |
| 알림 | `GET /notifications`, `GET /notifications/unread-count`, `POST /notifications/{id}/read` | `(user)/_lib/mock.ts` |
| 피드 상세·댓글·좋아요 등 | `/feeds/{id}/**`, `/feeds/comments/**` | `(feed)/feeds`, `(feed)/main` |
| 데모 | `/demos/**` | `(feed)/demos` |
| 블로그 (댓글·좋아요·북마크·구독·시리즈·순위) | `/posts/{id}/comments`, `/posts/{id}/like·bookmark`, `/subscriptions/**` | `(user)/blog` |
| 미니홈피 | `/mini-homes/**` | `(user)/mini-home` |
| 랭킹 | `GET /rankings` | `(feed)/rankings` |
| 검색·뉴스·이벤트 | `/search/**`, `/events/**` | 각 라우트 |
| 내 정보·칩 | `/users/me/settings`, `/users/me/bookmarks`, `/coins/**` | `(feed)/my` |

> 프론트가 `MOCK_EXCEPT_DM` 없이 `API_ORIGIN`만 켜면 위 API를 실제로 호출하고, 백엔드에 없어서 화면이 깨진다. 백엔드 API를 하나 만들면 그 영역의 `isMockMode` 분기가 실서버를 타는지 확인한다.

## 4. 시드 계정으로 DM 화면 확인하기 (로컬)

```bash
# 1) 시드 넣기 (처음 한 번. 회원 ID 1~70을 고정으로 쓰므로 빈 DB에 넣는다)
psql -h localhost -U dipsource -d dipsource -f backend/scripts/dev-seed/seed-data.sql

# 2) 백엔드 (개발용 로그인을 켠다)
cd backend
DEV_LOGIN_ENABLED=true \
GITHUB_CLIENT_ID=test GITHUB_CLIENT_SECRET=test \
JWT_SECRET=local-dev-secret-at-least-32-characters-long \
FRONTEND_BASE_URL=http://localhost:3000 \
./gradlew bootRun

# 3) 프론트: frontend/.env.local (커밋하지 않음)
API_ORIGIN=http://localhost:8080
NEXT_PUBLIC_WS_URL=ws://localhost:8080/ws
MOCK_EXCEPT_DM=1
# → cd frontend && npm run dev
```

4. 브라우저에서 `http://localhost:3000/login/dev` → 시드 계정 하나를 눌러 로그인한다.
5. 다른 계정은 시크릿 창(또는 다른 브라우저)에서 `/login/dev`로 로그인한다.
6. 오른쪽 아래 **DM 버튼**을 누르면 DM 창이 열린다. 다시 누르면 닫힌다. (DM은 별도 페이지가 없다)

추천 계정: `시드팀01`(#21)과 `시드팀02`(#22). 서로 팔로우 중이라 맞팔(`isMutualFollow`) 확인에도 쓸 수 있다.

> DM 창 목록에는 **이미 대화한 상대만** 나온다. 새 대화는 팔로우 목록·데모 상세의 DM 버튼으로 시작하는데, 팔로우 목록 API가 아직 스텁(빈 목록)이라 지금은 화면에서 새 대화를 시작할 수 없다. 팔로우 API가 생기면 해결된다. 그 전까지는 시드 계정끼리 WebSocket(`/app/dm.send`)으로 첫 메시지를 한 통 보내 두면 양쪽 DM 창에 대화방이 생긴다.

> 시드와 개발용 로그인은 **로컬 전용**이다. 배포 서버에서는 `DEV_LOGIN_ENABLED`를 켜지 않는다.

## 5. 백엔드가 완성되면 할 일

1. `client.ts`의 `isMockMode`를 `!hasBackend`로 되돌리고 `MOCK_EXCEPT_DM` 줄과 주석을 지운다.
2. `(user)/_lib/api.ts` `getMe`의 `isMockMode ? { ...mockMe, ...data } : data`를 `data`로 바꾼다.
3. `frontend/.env.local.example`의 `MOCK_EXCEPT_DM` 항목을 지운다.
4. 이 문서를 지우거나 남은 목업만 남긴다.
