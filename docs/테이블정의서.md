# 찍먹 — 테이블 정의서 (47 Tables)

> JPA 엔티티(`backend/src/main/java/com/dipsource/entity`)와 ERDCloud 기준. 둘이 다르면 엔티티가 기준이다.

- 단일 PK `id`는 모두 `bigint` AUTO_INCREMENT(IDENTITY)다. PK가 두 컬럼이면 복합 PK다.
- 관리자는 별도 테이블 없이 `users.role = 'ADMIN'`으로 구분한다. 관리자 ID 컬럼은 모두 `users(id)`를 가리킨다.
- `TEXT` 대신 길이를 정한 `varchar(n)`을 쓴다.
- `FK`로 적은 컬럼 중 엔티티가 연관관계 없이 id만 가지는 경우는 설명에 `(id만)`으로 표시한다.
- 상태값은 Java enum 이름을 문자열로 저장한다(`@Enumerated(EnumType.STRING)`).

### 1-6. refresh_tokens (Refresh Token)

| 컬럼명 | 타입 | 제약조건 | 설명 |
|--------|------|----------|------|
| id | bigint | PK | |
| user_id | bigint | FK → users(id), NOT NULL | 회원 (id만) |
| jti | varchar(36) | NOT NULL, UNIQUE | JWT `jti` |
| token_hash | varchar(64) | NOT NULL, UNIQUE | SHA-256 hex. 원문 JWT는 저장하지 않음 |
| family_id | varchar(36) | NOT NULL | 한 로그인 줄. 탈취 시 이 줄만 폐기 |
| issued_at | timestamp | NOT NULL | JWT `iat`. 유예 때 같은 토큰을 다시 서명할 때 사용 |
| expires_at | timestamp | NOT NULL | JWT `exp` |
| rotated_at | timestamp | | 교체 시각. NULL이면 현역 |
| revoked_at | timestamp | | 로그아웃·탈취·탈퇴 폐기 시각 |
| replaced_by_jti | varchar(36) | | 교체 후 다음 토큰의 jti. 30초 유예 재전송용 |
| created_at | timestamp | NOT NULL | |

- INDEX(user_id), INDEX(family_id), INDEX(expires_at)
- 갱신 시 기존 행에 `rotated_at`을 넣고 새 행을 INSERT한다.
- 교체 후 30초 안 재요청은 탈취가 아니라, 교체 체인의 맨 끝(아직 현역인 토큰)을 다시 준다. A→B→C면 A 재요청은 C다.
- 같은 family의 갱신·폐기는 `pg_advisory_xact_lock`으로 한 트랜잭션씩만 진행한다.
- 30초가 지난 재사용은 `family_id`가 같은 행만 폐기한다. 다른 기기 세션은 유지한다.
- 스케줄러는 `expires_at`이 지난 행만 지운다. 교체된 행을 바로 지우면 재사용 감지를 못 한다.

- 조회수 집계와 별개다. 180일이 지나면 삭제하고, 회원 탈퇴 시 삭제한다.

### 12-4. search_keyword_logs (인기 검색어 기록)

| 컬럼명 | 타입 | 제약조건 | 설명 |
|--------|------|----------|------|
| id | bigint | PK | |
| keyword | varchar(100) | NOT NULL | 정규화한 검색어. 2~50자(코드 포인트)만 저장 |

- 검색 결과 방문(`search_visits`)과는 별개다. 같은 로그인 사용자가 같은 검색어를 10분 안에 반복하면 한 번만 남긴다.
