## 1. 화면과 API

```
[프론트엔드]                              [백엔드]  모든 경로 앞에 /api/v1
/mini-home/[userId] (홈)            ←→  GET  /mini-homes/{userId}
  방문자 수 (VisitCounter)           ←→  POST /mini-homes/{userId}/visits, GET .../visitors
  일촌평                             ←→  GET·POST /mini-homes/{userId}/comments, DELETE /mini-homes/comments/{id}
  칩 후원 (SponsorButton)            ←→  POST /mini-homes/{userId}/donations  { chips }
  파도타기                           ←→  GET  /mini-homes/random?exclude=
/mini-home/[userId]/guestbook       ←→  GET·POST /mini-homes/{userId}/guestbook, DELETE /mini-homes/guestbook/{id}
/mini-home/[userId]/edit (꾸미기)    ←→  PUT  /mini-homes/me
                                         PUT  /mini-homes/me/featured-demo   대표 데모
                                         PUT  /mini-homes/me/featured-post   대표 글(제작기 글)
/mini-home/[userId]/demos           ←→  GET  /demos?userId=  (데모 기능)
```

- 미니홈피 API는 모두 **로그인 필수**다. 비로그인이면 401.
- 응답은 `{ "data": ... }` (`ApiResponse<T>`), 목록은 `PageResponse` (최신순).

## 3. 설계 결정

### 3.1 일촌평은 맞팔만
일촌은 서로 맺는 관계라 **서로 팔로우**한 사이만 쓸 수 있게 했다. 따로 일촌 테이블을 만들지 않고 `follows`로 판단한다(`FollowService.isMutualFollow`). 한 사람이 같은 홈에 하나만 남기도록 `(home_id, writer_id)` 유니크 키를 두고, 다시 쓰면 수정한다.

### 3.2 비밀글은 서버에서 숨김
비밀 방명록의 내용은 **작성자와 주인에게만 응답에 넣는다.** 다른 사람에게는 `content`를 빼고(null) `secret: true`만 준다. 프론트에서 가리기만 하면 응답을 열어 볼 수 있으므로 서버에서 막는다.

### 3.3 방문 수는 원자적으로 센다
```sql
UPDATE mini_homes SET today_count = today_count + 1, total_count = total_count + 1 WHERE user_id = ?
```
엔티티를 읽고 +1 해서 저장하면 동시 방문에서 값이 사라진다. DB가 한 번에 더하게 해서 동시에 들어와도 빠지지 않는다. 새로고침 중복은 프론트 `VisitCounter`의 `useRef`로 같은 화면에서 한 번만 보낸다.

### 3.4 자정 초기화 스케줄러
`MiniHomeVisitScheduler`가 **서울 시간 00:00**(`cron = "0 0 0 * * *", zone = "Asia/Seoul"`)에 모든 홈의 `today_count`를 한 번의 UPDATE로 0으로 만든다. 서버 시간대와 상관없이 한국 자정 기준이다.

### 3.5 대표 글 자동 해제
대표 글로 고른 글이 나중에 삭제·숨김되면, 홈을 조회할 때 확인해서 **연결을 자동으로 끊는다.** 깨진 링크를 내려주지 않기 위해서다. 고를 때도 내 공개 글인지 확인한다(`PostService.isActivePostOf`).

### 3.6 조회만으로는 홈을 만들지 않음
홈이 없는 회원을 조회하면 **저장하지 않은 기본값**(닉네임 제목, cream)으로 응답한다. 행은 처음 저장(PUT)하거나, 남이 방문해서 카운트가 필요하거나, 후원을 받을 때 만든다(`MiniHomeLoader.loadOrCreate`). 구경이나 크롤러 때문에 빈 행이 쌓이지 않는다.

### 3.7 스킨·BGM·도메인은 서버에서도 검증
프론트에도 같은 검사가 있지만 API를 직접 부르면 우회된다. 서버에서 목록·형식을 다시 확인하고, 예전에 저장된 이상한 값은 조회할 때 기본값(cream, BGM 없음)으로 보여 준다. 스킨·곡을 추가하면 **백엔드 `MiniHomeServiceImpl`과 프론트 목록을 같이 바꿔야 한다.**

### 3.8 후원은 두 회원을 ID 순서로 잠금
후원자와 받는 사람을 항상 **작은 ID부터** `SELECT … FOR UPDATE`로 잠근다. A↔B가 동시에 서로 후원해도 교착 상태가 생기지 않는다. 잔액이 부족하면 예외로 전체가 롤백되고, 모두 성공한 뒤에만 알림을 만든다.

## 4. 파일 구조 (백엔드)

```
controller/minihome/MiniHomeController.java      미니홈피·일촌평·방명록·후원 API
service/minihome/MiniHomeService (+impl)         조회·수정·방문·파도타기·대표 데모/글
service/minihome/MiniHomeCommentService (+impl)  일촌평
service/minihome/GuestbookService (+impl)        방명록
service/minihome/impl/MiniHomeLoader             홈 조회·생성 (같은 패키지 전용)
service/minihome/impl/MiniHomeVisitScheduler     자정 초기화
service/donation/DonationService (+impl)         후원
service/notification/NotificationService (+impl) 알림 (notify 공통 메서드)
repository/minihome/                             MiniHome, MiniHomeComment, Guestbook
```

## 5. 시연 데이터

`seed-data.sql`(회원·팔로우)을 넣은 뒤:
```
psql -U dipsource -d dipsource -f backend/scripts/dev-seed/seed-minihome.sql
```
미니홈피 10개, 일촌평 20개, 방명록 20개(비밀글 포함)가 들어간다. `/login/dev`에서 **시드팀01** 로그인 → `/mini-home/22`.

| 파도타기 차단 제외 | 지금은 차단한 회원의 홈도 뽑힐 수 있음 (들어가면 404) |
