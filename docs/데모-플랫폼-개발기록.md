# 데모 플랫폼 개발 기록

> 찍먹 안에서 사용자가 만든 웹 데모를 올리고 실행하는 기능의 개발 기록이다. 실제 코드와 테스트 결과만 적는다.
> 설정 방법은 [데모-플랫폼-배포.md](./데모-플랫폼-배포.md)를 본다.

## 전체 구조

```
브라우저 ── iframe sandbox ──▶ Worker(workers.dev) ──▶ R2(비공개)
   │                                  ▲
   └── Next.js ──▶ Spring Boot ───────┘ 공개 포인터(publication.json) 쓰기
                      │
                  PostgreSQL
```

| 구성 요소 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| Spring Boot | 메타데이터, ZIP 검증, 업로드, 공개·버전 관리 | 사용자 코드 실행 |
| PostgreSQL | 데모, 버전, 댓글, 좋아요 | 파일 저장 |
| R2 | 버전별 정적 파일, 공개 포인터 | 공개 접근 |
| Worker | 공개 포인터 확인 후 파일 제공, CSP·CORS | 파일 수정, 서버 코드 실행 |
| 브라우저 | 업로드된 JavaScript 실행 | — |

# 1차 — 정적 데모 실행

## 사용 기술과 선택 이유

| 기술 | 선택 이유 | 비교한 대안 |
| --- | --- | --- |
| Cloudflare R2 | 프로젝트에 이미 S3 SDK·R2 설정이 있어 재사용. 다운로드 비용 없음 | 강사님 서버 디스크(사용자 파일이 서비스 서버에 쌓이고 Nginx 변경 필요), S3(다운로드 비용) |
| Cloudflare Workers | R2 Binding으로 버킷을 비공개로 둔 채 요청마다 공개 여부를 판단. workers.dev로 DNS 변경 불필요 | R2 공개 버킷(비공개·이전 버전 차단 불가), Spring Boot 프록시(서비스 서버 대역폭 사용, 같은 출처 위험) |
| iframe `sandbox="allow-scripts"` + CSP sandbox | 데모가 opaque origin에서 실행되어 찍먹 쿠키·저장소·부모 DOM에 접근 불가 | 새 창 열기(체험 흐름 끊김), `allow-same-origin`(sandbox 탈출 가능) |
| 직접 파싱한 ZIP 중앙 디렉터리 + `java.util.zip.ZipFile` | JDK ZIP API는 심볼릭 링크 정보를 주지 않음. 새 의존성 없이 검사 | commons-compress(의존성 추가) |

## 구현한 기능

- 데모 CRUD, ZIP 업로드, 버전 저장, 공개·공개 해제, 좋아요, 북마크, 실행 수, 댓글(답글·수정·삭제·좋아요), 커서 목록
- Worker: GET/HEAD 전용 파일 제공, MIME, CSP, CORS, 경로 검증
- 프론트: 목록·등록·상세·iframe 실행·관리(수정·삭제·새 버전·공개)

## 주요 설계 결정

**공개 포인터.** Worker는 `demos/{id}/publication.json`을 읽어 그 안의 `versionId`와 URL의 버전이 같을 때만 파일을 준다. 공개 해제·삭제는 이 객체를 지우는 것으로 즉시 차단되고, 이전 버전은 파일이 남아 있어도 URL로 열리지 않는다.

**R2와 DB의 정합성.** 두 저장소는 한 트랜잭션으로 묶을 수 없다.

| 작업 | 처리 |
| --- | --- |
| 업로드 | 검증을 끝낸 뒤에만 R2로 보냄. DB 트랜잭션을 잡지 않고 전송하고, 실패하면 올린 파일을 지우고 버전을 FAILED로 표시 |
| 공개 | 데모 행을 잠근 채 커밋 직전에 포인터를 씀. 쓰기 실패 → DB 롤백. 커밋 실패 → 이전 포인터로 복원 |
| 삭제 | 포인터를 지운 뒤 커밋. 파일은 정리 작업이 지우고, 성공해야 DELETED가 되므로 R2 장애 시 다음 주기에 재시도 |

**DRAFT 상태 추가.** 업로드 전에 메타데이터를 만들어야 해서 `demos.status`에 DRAFT를 넣었다. 기존 검색·신고 쿼리는 `status = 'ACTIVE'`로 걸러서 초안이 새지 않는다.

**CSP에 `'self'`를 쓰지 않음.** sandbox 문서의 출처는 opaque라 `'self'` 해석에 기대지 않고 버전 경로를 직접 적었다(`https://…/demos/1/versions/2/`). 다른 데모의 스크립트를 불러오는 것도 막힌다.

**HTML 외 응답에도 CSP sandbox.** SVG를 주소창으로 직접 열어 스크립트를 실행하는 경로를 막는다.

**임시 파일 이름.** ZIP 안의 이름을 파일 시스템에 쓰지 않고 `f0`, `f1` 일련번호로 저장해 ZIP Slip이 구조적으로 불가능하다. 경로 검사는 R2 키를 위한 것이다.

## 실제 발생한 문제와 해결

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 기존 DB에 DRAFT를 넣을 수 없음 | Hibernate가 만든 `demos_status_check`를 `ddl-auto=update`가 고치지 않음 | `schema.sql`에서 제약 삭제 |
| Vite 기본 빌드가 하위 경로에서 404 | `src="/assets/…"`는 도메인 루트 기준 | 업로드 시 탐지해 `base: './'` 안내와 함께 거부 |
| 응답의 null 필드 누락 | `default-property-inclusion: non_null` | 삭제된 댓글을 프론트에서 null로 정규화 |
| 큰 업로드가 500이 될 수 있음 | `MaxUploadSizeExceededException` 처리 없음, 기본 multipart 한도 1MB | 12MB로 설정, 413 응답 추가 |
| wrangler `persistTo`와 `getPlatformProxy`가 저장소를 공유하지 않음 | 테스트 데이터가 Worker에서 보이지 않음 | 테스트 전용 진입점에 시드 경로를 둠 (`test/harness.js`, 배포본 제외) |

## 1차 테스트 결과

| 대상 | 방법 | 결과 |
| --- | --- | --- |
| ZIP 공격 방어 (Slip, Bomb, 헤더 위조, 심볼릭 링크, 특수 파일, 암호화, 손상, 덧붙은 데이터, 중복, 형식, 용량) | JUnit `DemoZipValidatorTest` | 48건 통과 |
| 생성 → 업로드 → 공개 → 소비 → 삭제, 권한, 보상 처리 | JUnit `DemoFlowTest` (실제 PostgreSQL, R2는 메모리 구현) | 22건 통과 |
| Worker 경로·CSP·CORS·메서드·포인터 | `node --test` + wrangler 로컬 런타임 | 18건 통과 |
| 실제 React·Vue 빌드 실행 | Vite 빌드 → 로컬 Worker → Headless Chrome의 sandbox iframe | 렌더링·클릭·동적 청크 정상. 쿠키·localStorage·부모 DOM 접근 SecurityError, 외부 fetch CSP 차단, 허용하지 않은 부모의 iframe 차단 |

**미검증:** 실제 Cloudflare R2/Workers(계정·토큰 없음). 로컬 런타임(workerd)과 실제 환경의 차이는 배포 후 확인이 필요하다. `R2DemoStorage`의 S3 API 사용은 3차에서 S3 호환 테스트 서버로 검증했다.

## 남아 있는 한계

- `location.href` 등으로 iframe 자신을 외부 페이지로 이동시키는 것은 CSP로 막을 수 없다(`navigate-to` 폐기). 부모·쿠키에는 닿지 못한다.
- 모든 데모가 같은 workers.dev 출처를 쓴다. 격리는 opaque origin에 의존한다.
- 요청마다 포인터를 R2에서 읽어 파일 하나당 Class B 작업이 2회 든다.
- 포인터를 쓴 직후 서버 프로세스가 죽으면 복원이 실행되지 않아 포인터가 DB보다 앞설 수 있다.
- 악성 코드 검사(VirusTotal)는 하지 않는다. 실행 격리로 대응한다.

# 2차 — 사용자 편의성 개선

## 사용 기술과 선택 이유

| 기술 | 선택 이유 | 비교한 대안 |
| --- | --- | --- |
| 브라우저 `DecompressionStream` + srcdoc | 라이브러리 없이 ZIP을 풀어 서버 전송 없이 미리 봄 | JSZip(의존성 추가), Blob URL(상대 import 재현 불가) |
| HMAC 서명 URL (Worker에서 검증) | 경로 안에 토큰을 넣어 상대 경로 자산이 그대로 동작. DB 조회 없이 Worker가 판단 | 쿼리스트링 토큰(하위 자원에 전달 안 됨), 쿠키(sandbox에서 사용 불가) |
| Cloudflare Browser Run screenshot API | 신뢰할 수 없는 데모를 격리된 원격 브라우저에서 실행 | 서버의 Playwright(사용자 코드가 서비스 서버에서 실행됨), 직접 띄운 격리 브라우저(운영 부담) |
| DB 폴링 스케줄러 (썸네일) | 재시작해도 대기가 유지되고 호출 간격 제어가 쉬움 | `@Async`(재시작 시 유실), 메시지 큐(규모 대비 과함) |
| 조건부 UPDATE 예약 (용량) | 비교와 증가가 한 문장이라 행 잠금 안에서 판단됨 | SUM 쿼리 후 비교(동시 요청에 뚫림), 사용자 단위 분산 락(불필요한 복잡도) |
| 주입 스크립트 + postMessage (실행 감지) | SDK 없이도 boot·load·오류를 알 수 있음. `dipDemo.ready()`로 정확도를 높일 수 있음 | iframe `onLoad`(빈 화면·JS 오류에도 호출됨) |

## 구현한 기능

- **미리보기.** A: 단순 HTML/CSS/JS는 브라우저에서 풀어 인라인한 srcdoc으로 실행(서버 전송 없음). B: ES 모듈·동적 import·fetch를 쓰는 프로젝트는 임시 업로드 후 서명 URL로 실행(화면에 전송 사실을 표시, 30분 후 삭제). 판단은 `planPreview`가 한다.
- **자동 썸네일.** 버전 저장 → 대기 → 서명 URL로 촬영 → 640×400 JPEG → R2 → `thumbnail` 갱신. 3회 재시도 후 기본 썸네일, 실패 원인 기록, 수동 업로드 우선.
- **버전 복구.** 버전 목록, 파일 정보, 현재 공개 표시, 이전 버전 복구, 버전 미리보기, 보관 버전 삭제.
- **실행 실패 감지.** 로딩·실패·다시 시도·문제 신고 UI.
- **사용량.** 데모 수·총 용량·데모별 버전 수 제한, 남은 용량 표시.

## 주요 설계 결정

**복구는 포인터만 바꾼다.** 공개와 같은 경로를 타며 R2 쓰기는 포인터 한 번이다. 공개 전에 저장소의 파일 수·크기를 DB와 비교해 다르면 409로 거부하므로 현재 공개 버전이 유지된다.

**동시 변경.** 데모 행 `PESSIMISTIC_WRITE`로 직렬화하고, 화면이 본 현재 버전(`expectedCurrentVersionId`)과 다르면 409를 준다. 동시 복구는 하나만 성공한다.

**R2 호출 중 행 잠금.** 포인터 쓰기와 커밋 순서를 지키려고 공개 시에는 짧게 잠금을 유지한다. 업로드 전송은 잠금 밖에서 한다.

**용량 예약 흐름.** 예약 → 전송 → 성공 시 사용량으로 이동 / 실패 시 반환. 서버가 죽어 남은 예약은 정리 작업이 UPLOADING이 1시간 멈춘 버전을 찾아 돌려준다.

**메시지 신뢰 범위.** 데모 코드는 nonce를 읽을 수 있어 메시지를 위조할 수 있다. 그래서 `source === iframe.contentWindow`, `origin === "null"`, 구조, nonce, 타입 허용 목록을 검사한 뒤에도 해당 사용자 화면의 안내만 바꾼다. 서버 상태는 건드리지 않는다.

## 오류 감지 범위

| 상황 | 감지 | 방법 |
| --- | --- | --- |
| HTML 404, Worker 5xx | O | Worker가 iframe용 오류 HTML에서 메시지 전송 |
| JS·CSS 누락 | O | capture 단계 error 이벤트 |
| 초기화 중 예외, Promise 거부 | O | window error / unhandledrejection |
| 응답 없음, 초기화 지연 | O | 20초 시간 초과 |
| CSP 위반 | 경고 | securitypolicyviolation |
| `dipDemo.error()` 호출 | O | 데모 작성자 SDK |
| 빈 화면인데 오류는 없음 | **X** | `dipDemo.ready()`를 안 부르면 판별 불가 |
| 앱 내부 로직 오류(잘못된 동작) | **X** | 브라우저가 알 수 없음 |
| 스크립트가 무한 루프로 멈춤 | **X** | 같은 프로세스일 수 있어 메시지도 안 옴. 이미 `loaded` 후면 감지 불가 |
| 이미지 누락 | 경고 | 실행은 계속될 수 있어 막지 않음 |

## 실제 발생한 문제와 해결

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 삭제 처리 뒤 버전이 READY로 남음 | 용량 UPDATE의 `clearAutomatically`가 영속성 컨텍스트를 비워 뒤이은 상태 변경이 저장되지 않음. 통합 테스트에서 발견 | 상태를 먼저 바꾸고 용량 UPDATE 실행 |
| 임시 미리보기 URL의 상대 경로 | 쿼리 토큰은 하위 요청에 안 붙음 | 토큰을 경로에 넣어 `./assets/…`가 같은 토큰 아래로 해석되게 함 |
| 서명 범위 위조 가능성 | 서명 대상 경로를 URL에서 받음 | scope 전체에 서명하고, 서명이 맞아도 허용 접두사 정규식을 다시 검사 |

## 남아 있는 한계

- 미리보기 개수 제한은 조회 후 비교라 동시 요청에서 살짝 넘을 수 있다. 저장 용량은 원자적 예약으로 보호된다.
- 무료 플랜은 하루 브라우저 10분이라 초과 시 재시도를 소진해 기본 썸네일이 된다. 수동 재생성 기능은 없다.
- 서버 인스턴스를 여러 개 띄우면 썸네일 스케줄러가 같은 버전을 중복 촬영할 수 있다(현재 단일 인스턴스).

# 3차 — 데모 개발 환경 확장

## 사용 기술과 선택 이유

| 기술 | 선택 이유 | 비교한 대안 |
| --- | --- | --- |
| Worker에서 정적 JSON 응답 (Mock API) | 데모별 서버 없이 기존 Worker만 확장. 사용자 코드를 서버에서 실행하지 않음 | Spring 프록시(서비스 서버 부하, 같은 출처 문제), Service Worker 주입(sandbox opaque origin에서 등록 불가) |

| 클래스패스 고정 템플릿 | 찍먹이 관리하는 코드만 배포 | DB 저장(임의 등록 경로가 생김) |

## 구현한 기능

- **Mock API.** `/demos/{id}/versions/{ver}/__mock/...`. 등록한 메서드·경로만 정적 응답. GET/POST/PUT/PATCH/DELETE, 200번대·400·500번대 상태. 미등록 404, 메서드 불일치 405.
- **샘플 데이터.** JSON 작성, 문법 검사(행·열 표시), 미리보기, 크기(256KB)·중첩(16단계) 제한, `dataKey`로 Mock 응답 연결, 버전별 관리.
- **코드 편집기.** HTML·CSS·JS·Mock·샘플 데이터 탭, 실행, 초기화, 저장. 결과는 `index.html`·`style.css`·`script.js` 정적 파일 버전이 된다.
- **템플릿.** 계산기, 드래그 앤 드롭 보드, 반응 속도 미니게임. 코드·샘플 데이터·사용 방법·미리보기·편집·저장을 포함한다.

## 주요 설계 결정

**경로별 권한 분리.** 쓰기 메서드와 OPTIONS는 `__mock` 경로에서만 받는다. 정적 파일 경로의 GET/HEAD 제한과 CSP는 바꾸지 않았다. 데모 CSP의 `connect-src`가 원래 자기 버전 경로만 허용하므로 Mock을 위해 넓힐 필요가 없었다.

**Mock은 아무것도 저장하지 않는다.** Worker는 요청 본문을 읽지 않고 R2 읽기만 한다. 설정에는 `method`, `path`, `status`, `response`, `dataKey`만 허용해 스크립트가 들어갈 자리가 없다.

**설정 변경은 새 버전.** 공개 중인 버전을 고치지 않으므로 복구하면 Mock도 함께 돌아온다. 파일을 공유하는 버전 중 원본을 지우면 파일과 용량 부담을 남은 버전으로 넘기고, 마지막 버전이 지워질 때 파일을 지운다.

**편집 결과도 같은 경로.** 코드 편집 저장은 임시 파일로 만든 뒤 ZIP과 같은 `store`를 지나 용량·버전 수·절대 경로 검사를 그대로 받는다.

## 남아 있는 한계

- 편집기 미리보기의 Mock은 `fetch`만 대체한다. `XMLHttpRequest`는 저장 후 실제 Worker에서만 동작한다.
- Mock 경로는 정확히 일치해야 하며 `/users/:id` 같은 패턴은 없다.
- 공개 데모의 Mock 응답은 누구나 읽을 수 있다. 개인정보 입력은 화면 안내로만 막는다.
- 호출 횟수 제한(rate limit)이 없다. 필요하면 Cloudflare 규칙으로 건다.
